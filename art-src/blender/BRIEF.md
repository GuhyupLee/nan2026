# 작업자 브리핑 — Blender 환경 에셋

이 문서 하나만 읽고 바로 시작할 수 있어야 한다.

## 먼저 읽을 것 (순서대로)

1. `art-src/blender/SPEC.md` — 좌표·반경·예산·에셋 목록. **계약이다.**
2. `art-src/blender/lib/mw.py` — 쓸 수 있는 함수 전부. 여기 없는 건 만들지 말고
   `bmesh`/`bpy`를 직접 써라.
3. `art-src/blender/assets/10_tex_ground.py` — **품질 기준 예시.** 주석 밀도, 값을
   고른 이유를 적는 방식, 구조를 그대로 따라라.

## 실행

```bash
node tools/blender/run.mjs art-src/blender/assets/<파일>.py
```

- 이 러너는 **락으로 직렬화**된다. 다른 작업자가 Blender를 쓰는 중이면
  `[blender-queue] 대기 중` 로그가 뜨고 순서를 기다린다. **정상이다. 죽이지 마라.**
- 절대 `blender.exe`를 직접 부르지 마라. 큐를 건너뛰면 동시 실행으로 서로 느려진다.
- Blender GUI가 데스크탑에 떠 있어도 무시하라. 이 파이프라인은 헤드리스다.

텍스처를 만든 뒤에는:

```bash
node tools/art/optimize-env-tex.mjs
```

## 절대 규칙

1. **결정성.** `random`, `Math.random`, 시간, 전역 상태 금지. 난수는 `mw.rng("salt")`
   뿐이다. 같은 스크립트를 두 번 돌리면 같은 바이트가 나와야 한다.
2. **`mw.reset(seed=N)`의 N은 파일마다 고유해야 한다.** 겹치면 두 에셋의 배치
   난수가 같아져 눈에 띈다. 파일명 접두 숫자 × 100을 쓰면 안전하다.
3. **텍스처를 새로 만들기 전에 매니페스트를 확인하라.** `art-src/blender/manifest.json`에
   이미 있는 머티리얼은 그대로 재사용한다 — 같은 이름을 쓰면 three.js가 드로우콜을
   합친다. 새로 만들면 예산만 먹는다.
4. **`max_triangles`를 반드시 넘겨라.** SPEC의 예산값을 그대로 쓴다.
5. **베벨 없는 모서리 금지.** `mw.bevel(obj, 0.008~0.03, 2)`. 이것 하나가 웹게임과
   상용의 경계다.
6. **평평한 원판 금지.** 지면이든 벽이든 정점 단위 변형이 있어야 한다.
7. 오브젝트 원점은 **바닥 중심**, 정면은 **Blender +Y**.

## 자주 하는 실수

- `mw.uv_box(obj, scale)`는 **월드 공간** 투영이다. 오브젝트를 회전시킬 거면
  UV를 먼저 펴고 회전하지 마라 — 배치는 three.js가 한다.
- `mw.lathe`의 프로필은 `(반지름, z)` 쌍이다. `(x, y)`가 아니다.
- `mw.sweep`의 단면은 `(가로, 세로)` 2D다. 경로 접선이 up과 평행해지면 프레임이
  뒤집히니 수직 경로에는 `up=(0,1,0)`을 넘겨라.
- 스무딩: `mw.shade_auto_smooth(obj, 각도)`. 그냥 `shade_smooth()`만 하면 평면이
  둥글게 뭉개진다.
- 삼각형 예산 초과는 **디테일을 지우는 게 아니라** `mw.decimate()` 또는
  하이폴리→노멀 베이크(`mw.bake_high_to_low`)로 옮기는 것으로 해결한다.

## 끝내기 전 확인

`SPEC.md` §7 자체 점검 목록을 전부 통과했는지 확인하고, 각 에셋의 삼각형 수와
GLB 크기를 보고하라. 실패한 항목이 있으면 숨기지 말고 그대로 보고하라.
