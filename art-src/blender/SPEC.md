# 명월 아레나 — 환경 아트 스펙

이 문서는 Blender 에셋 스크립트와 three.js 환경 레이어가 **동시에** 따르는 계약이다.
여기 적힌 좌표·반경·이름을 바꾸면 양쪽이 같이 깨진다.

목표는 하나다: **일반적인 웹게임에서 볼 수 없는 외관.** 기준선은 이터널 리턴이다.
"three.js 데모"와 "상용 게임"을 가르는 것은 삼각형 수가 아니라 아래 다섯이다.

1. 진짜 PBR — 베이스컬러 / 노멀 / ORM 세 장이 모든 표면에 있다. 단색 없음.
2. 베벨 — 완벽히 날카로운 모서리는 실존하지 않는다. 스페큘러가 모서리를 타야 한다.
3. 하이폴리 노멀 전사 — 로우폴리 실루엣 + 고밀도 표면.
4. 깊이 — 아레나 밖 실루엣(성벽 → 절벽 → 능선 → 하늘)이 4겹 이상 겹쳐야 한다.
5. 국소 광원 — 석등·화로의 발광이 주변 표면을 실제로 물들여야 한다.

---

## 1. 세계관과 장소

**명월단(明月壇)** — 산성(山城) 정상의 원형 제단. 오래 버려졌고, 개기월식 아래 있다.
달은 원을 파고 해는 선을 긋는다는 게임의 문장이 바닥 상감과 건축 문양에 반복된다.

5분 동안 월식이 진행되며 환경 전체가 4단계로 물든다 (`ArenaArc`).

| 단계 | 시각 | 하늘 | 광원 | 분위기 |
|---|---|---|---|---|
| `base` | 0:00~ | 차가운 청람, 만월 | 푸른 달빛, 긴 그림자 | 정적, 서늘함 |
| `dusk` | 0:55~2:30 | 청보라, 달 일부 잠식 | 달빛 약화, 석등 부각 | 불안 |
| `eclipse` | 2:25~3:30 | 자홍 코로나 링 | 자홍 산란광 | 이질감 |
| `boss` | 보스 등장 | 혈적색, 달 완전 잠식 | 붉은 반사광, 안개 상승 | 적대 |
| `phaseTwo` | 2페이즈 | 균열된 하늘 | 지면 발광 균열 | 붕괴 |

**색은 절대 텍스처에 굽지 않는다.** 텍스처는 중성 그레이스케일에 가깝게 만들고,
아크 색조는 three.js 셰이더 유니폼이 입힌다. 그래야 5장 텍스처로 5단계를 다 낸다.

## 2. 좌표 계약

- 단위 = 미터. `ARENA_RADIUS = 30`.
- **Blender는 Z-up**으로 작업한다. 익스포터가 glTF Y-up으로 바꾼다.
- 지면 = Blender `z = 0`. 아레나 중심 = `(0, 0, 0)`.
- **정면은 Blender +Y.** 변환 후 three.js -Z가 되어 `lookAt`이 그대로 맞는다.
- 개별 프롭은 **자기 원점에 서 있게** 만든다(바닥 중심이 원점). 배치는 three.js가 한다.
- 링 구조물(성벽 등)은 스펙에 적힌 반경에 **이미 굽은 상태로** 만든다.

### 반경 레이아웃 (아레나 중심에서 바깥으로)

| 반경 | 내용 | 높이 제한 |
|---|---|---|
| 0.0 – 4.6 | 월대(月臺) 상감 — 초승 문양, 저부조 | 바닥 ±0.06 |
| 0.0 – 27.5 | 화강암 판석 광장 (전투 공간) | 바닥 ±0.04 |
| 27.5 – 30.0 | 마모대 — 이끼, 균열, 모래 퇴적 | 바닥 ±0.05 |
| 30.0 – 31.6 | 낮은 석연(石緣)과 계단 3단 | ≤ 0.42 |
| 31.6 – 33.2 | 외곽 회랑(테라스) — 석등, 화로, 잔해 | ≤ 2.6 |
| 33.2 – 34.8 | **성벽** 본체 + 여장 | 본문 §4 참조 |
| 35 – 44 | 바깥 지형 — 바위 단, 소나무, 대나무 | ≤ 9 |
| 44 – 90 | 절벽 낙차 + 안개 띠 | 아래로 |
| 90 – 400 | 원경 능선 3겹 | ≤ 70 |

### 가시 범위 — 계산이 아니라 실측이다

`src/render/env/devshot.ts`의 `probe()`로 반경별 높이 눈금 기둥을 세우고 실제로
찍어서 잰 값이다. **이 표를 무시하고 만든 에셋은 화면에 나오지 않는다.**

| 관측 | 결과 |
|---|---|
| 지평선 | **화면에 절대 들어오지 않는다.** 부감 52° − FOV 20° = 화면 최상단이 수평 아래 32° |
| 지면 가시 깊이 | 플레이어 기준 **뒤 6.3m ~ 앞 11.3m**. 화면 상단 기준 가로 폭 약 33m |
| 화면 상단에서 잘리는 높이 | 플레이어에서 11m 앞 = 0m. 4m 앞 = 약 4.5m. 바로 옆 = 약 8m |
| 원경 | r=20 이상은 화면 모서리에서만 스친다. **r=45 바깥은 어떤 높이든 보이지 않는다** |

따라서 우선순위가 이렇게 정해진다.

**S급 — 화면의 85%를 차지한다**
1. 지면 지오메트리·텍스처·정점 컬러 블렌드
2. **지면 높이 1.5m 이하의 조밀한 산포물** — 자갈, 잔해, 풀포기, 이끼 덩이,
   낙엽, 부러진 기와, 잔뿌리, 물웅덩이. 이게 "빈 바닥"과 "장소"를 가른다
3. 지면 조명 품질 — GTAO, 그림자, IBL
4. 근거리 대기 — 지면 안개, 부유 입자, 광선

**A급 — 가장자리에 섰을 때 하단 4~6m가 보인다**
5. 회랑·계단·성벽 하부
6. 석등(2m·전체 보임), 화로, 향로, 해태 석상, 석탑 하부
7. 식생 — 풀·고사리·관목, 나무는 줄기 하부만

**B급 — 드물게, 부분만 보인다**
8. 여장, 문루 하부, 바깥 지형 r=45까지

**만들지 않는다 — 절대 보이지 않는다**
- 원경 능선(`44_ridge.py`) — 삭제
- r=50 바깥 절벽 — `43_cliff.py`는 r=36~48 바위 둔덕으로 축소
- 지붕 위 장식, 종각 상부 등 높이 6m 초과 디테일 — 실루엣만 있으면 된다
- 하늘의 세부 — 하늘은 **IBL 광원으로만** 기여한다(이미 구현됨)

### 카메라 차폐 규칙 — **반드시 지킬 것**

카메라는 플레이어 + `(0, 14, 10.8)`, FOV 40, 부감 52°다. 플레이어가 남쪽 가장자리에
서면 **카메라가 성벽 바깥에 놓인다.** 그래서 두 가지를 동시에 한다.

- 기하 제한: 회랑(31.6–33.2)의 상시 구조물은 **2.6m 이하**. 성벽 본체는 3.4m 이하,
  문루·각루만 예외로 높다.
- 셰이더 차폐 페이드: three.js가 카메라–플레이어 사이에 들어온 구조물을 디더 컷아웃
  한다(`env/occlusion.ts`). 에셋 쪽에서 할 일은 없지만, **속이 빈 껍데기 금지** —
  잘려 나갔을 때 안쪽 면이 보여야 하므로 두께가 있어야 한다.

### Tier 1 — 텍스처 (지오메트리 없음)

| 스크립트 | 산출 | 해상도 |
|---|---|---|
| `10_tex_ground.py` | `granite-slab`, `worn-stone`, `moss-seam`, `sand-drift`, `wet-stone` | 2048 |

**전부 이음매 없이 타일링**되어야 한다 (`mw.fbm` / `mw.voronoi`는 이미 주기적이다).
베이스컬러는 채도를 낮게(HSV S ≤ 0.18) — 아크 색조가 위에 얹힌다.

### Tier 1.5 — 맵 지형 (바닥 자체가 모델링 대상이다)

바닥은 셰이더 평면이 아니라 **실제 지오메트리**다. 판석 하나하나가 인셋과 베벨을
가져야 이음매에 진짜 AO가 앉고, 모서리에 스페큘러가 흐른다. 셰이더로 그린 이음매는
정면에서만 그럴듯하고 부감 카메라에서 즉시 그림으로 읽힌다 — 이 게임 카메라가
정확히 그 각도다.

| 스크립트 | 에셋 | 삼각형 | 설명 |
|---|---|---|---|
| `15_plaza.py` | `plaza-floor` | ≤ 95,000 | r=0~30 판석 광장. 동심 링 배치, 판마다 인셋+베벨, 링마다 판 길이를 달리해 격자감 제거. 균열·파손 판·침하는 실제 정점 변위 |
| `16_altar.py` | `moon-altar` | ≤ 16,000 | r=0~4.6 월대. 2단 저부조 단, 초승 상감(별 오브젝트), 배수홈 |
| `17_terrace.py` | `outer-terrace` | ≤ 34,000 | r=30~33.2 석연·3단 계단·회랑 바닥. 계단은 실제 단 |
| `18_terrain.py` | `outer-terrain` | ≤ 70,000 | r=33~92 바깥 지형. 바위 단, 흙, 마른 계류, 절벽 시작부 |

바닥 규칙 — **게임플레이가 2D 시뮬이라 실제 높이는 거의 없어야 한다.**

- r ≤ 30 구간의 정점 z는 `[-0.05, +0.04]`를 절대 벗어나지 않는다. 캐릭터는 z=0
  평면 위를 걷고, 발이 파묻히거나 뜨면 즉시 보인다.
- 그 안에서 최대한 쓴다. 판석 침하 -0.02, 융기 +0.015, 이음매 -0.012 정도면
  부감에서 충분히 읽힌다. 평평한 원판과의 차이는 결정적이다.
- 정점 컬러에 정보를 굽는다: **R = 마모도**(0 새것 → 1 닳음), **G = 이끼/습기**,
  **B = 균열 근접도**. three.js가 이걸로 텍스처 3종을 높이 블렌드하고 젖음을 낸다.
  이 채널이 없으면 30m 전체가 같은 텍스처 하나로 보인다.
- 전투 가독성 상감(중앙 초승, 10m·20m 기준선, 진입로)은 **바닥 셰이더가 아니라
  별도 발광 상감 오브젝트**로 만든다. 이름 `plaza-inlay`. 그래야 아크에 따라
  따로 밝기를 올릴 수 있다.

## 5. 머티리얼 계약

`mw.MaterialSpec(shader=...)`가 three.js 확장을 고른다.

| `shader` | three.js 처리 |
|---|---|
| `default` | `MeshStandardMaterial` + 아크 색조 |
| `stone` | + 젖음 레이어, 이끼 높이 블렌드, 차폐 디더 |
| `foliage` | + 정점 컬러 R 가중 바람, 양면, 알파 테스트, 약한 투과 |
| `cloth` | + 바람 (진폭 큼), 양면 |
| `emissive` | + 블룸 승격, PointLight 생성, 아크 연동 깜빡임 |
| `water` | + 반사, 노멀 스크롤 |

머티리얼 이름은 `mw/<family>/<name>` 형식. 예: `mw/arch/masonry`, `mw/nature/pine-needle`.
**같은 텍스처 세트를 쓰는 에셋은 반드시 같은 머티리얼 이름을 쓴다.** three.js가
이름으로 묶어 인스턴싱하므로, 이름이 갈리면 드로우콜이 그만큼 늘어난다.

## 6. 스크립트 뼈대

```python
# -*- coding: utf-8 -*-
"""<에셋 이름> — 한 줄 설명."""
import os, sys
sys.path.append(os.path.join(os.environ["MW_PROJECT_ROOT"], "art-src", "blender", "lib"))
import numpy as np
import mw

mw.reset(seed=<고유 정수>)          # 시드가 겹치면 두 에셋의 난수가 같아진다

# ... 지오메트리 ...

mw.export_glb("<asset-name>", [obj], max_triangles=<예산>)
mw.finish()
```

실행:

```bash
node tools/blender/run.mjs art-src/blender/assets/<파일>.py
```

이 러너는 **락으로 직렬화**한다. 여러 작업자가 동시에 호출해도 Blender는 한 번에
하나만 돈다. 대기 로그가 뜨는 건 정상이다. 전체 재빌드는 `--all`.

## 7. 자체 점검 목록

에셋을 끝냈다고 말하기 전에 전부 통과해야 한다.

- [ ] +Y를 향한다
- [ ] 매니페스트에 머티리얼이 기록됐다
- [ ] 같은 스크립트를 두 번 돌리면 같은 바이트가 나온다 (결정성)
