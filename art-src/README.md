# art-src — 생성 원본

Codex CLI(`image_generation`)로 생성한 원본 이미지. 손으로 수정하지 않는다.

`npm run art` 가 이 디렉터리를 읽어 `public/art/` 에 WebP를 굽는다.

원본을 리포에 함께 두는 이유는 AI 활용 문서의 증거 사슬을 리포 안에서
끊기지 않게 하기 위해서다 — 생성 프롬프트, 생성 원본, 최적화 스크립트,
최종 산출물이 모두 같은 저장소에 있고 커밋 기록으로 순서가 남는다.

## 생성 이력

| 파일 | 세대 | 도구 | 용도 |
|---|---|---|---|
| `portraits/magic-girl.png` | 2차 (VRM 기준) | Codex CLI 0.145.0 · image_generation | 원딜 일현 — 캐릭터 선택·레벨업 초상 |
| `portraits/samurai-girl.png` | 2차 (VRM 기준) | Codex CLI 0.145.0 · image_generation | 근딜 월아 — 캐릭터 선택·레벨업 초상 |
| ~~1차~~ | 폐기 | 〃 | 인게임 모델을 VRM으로 교체하며 디자인이 어긋나 재생성 |

파일명은 `tools/optimize-art.ts`가 산출물 이름을 여기서 파생시키므로 고정이다.
1차 때 붙인 이름이라 `samurai-girl`이 더 이상 문자 그대로 맞지는 않는다.

두 장은 같은 프롬프트 세션에서 생성하고, 먼저 완성한 일현 초상을 월아의 화풍
기준으로 사용해 선 두께·채색·조명을 일치시켰다.

**캐릭터 디자인의 진실 원천은 VRM 모델이다.** 1차 초상은 손으로 쓴 텍스트
프롬프트만으로 만들었고, 나중에 VRoid로 실제 3D 모델을 만들자 머리색·의상·무기가
전부 어긋났다(1차 근딜은 흑발 포니테일 닌자, VRM은 청록 단발 치파오). 2차는
VRM 모델을 정면·3/4로 렌더한 이미지 4장을 codex에 첨부해 그것을 보고 그리게 했다.
같은 절차를 쓰면 모델을 바꿔도 초상을 다시 맞출 수 있다:

```bash
# 1. _model.html 하네스에서 참조 렌더 4장 생성
# 2. codex exec -s workspace-write -i ref-*.jpg - < 프롬프트
# 3. npm run art
```

## 클래스 컬러 언어

두 초상의 색 대비가 그대로 클래스 정체성이 된다. 인게임 VRM 모델과
스킬 이펙트가 이 팔레트를 따라야 2D와 3D의 정밀도가 달라도 같은 캐릭터로 읽힌다.

| 클래스 | 팔레트 | 인상 |
|---|---|---|
| 원딜 (일현) | 시안 `#4DD0FF` · 화이트 · 골드 | 차가운 빛, 정적, 거리 유지, 직선과 광선 |
| 근딜 (월아) | 크림슨 `#FF5A6E` · 블랙 · 실버 | 뜨거운 칼날, 역동, 파고들기, 원호와 초승달 참격 |
