# 개선안 ①~⑧ — 재미 중심 로드맵

작성 시점 HEAD: `995c310` (fix: align combat warnings and HUD).
기준: **80% 재미 / 20% 참신함**, 재미의 준거는 뱀파이어 서바이버즈(수집·빌드·학살)와
이터널리턴(QWER 표현·리듬·클라이맥스)이다.

이 문서는 P0(뱀서의 심장 이식) 4건 + 배선 1건, P1(리듬과 클라이맥스) 3건을 다룬다.
P2(참신함) 항목은 범위 밖이다.

## 2026-07-29 후속 개선

- 기본 XP 보석 자동 흡수 반경을 `2.5 → 4.0`으로 넓혔다. 반경 안의 모든
  보석을 독립적으로 판정해 최근접 하나뿐 아니라 처치 군집 전체가 동시에
  귀환한다. 전장 자석만 전역 흡수를 시작하는 규칙은 유지한다.
- 초반 XP 요구량을 `21/43/60/76 → 16/36/60/88`로 재배분했다. Lv2·Lv3
  중앙값은 약 12초·25초로 앞당기고, Lv5 누적 200과 전체 5,643 XP는 유지한다.
- 일반 강화와 QWER 연마는 최대 4택으로 넓혔다. 정예 전리품은 큰 선택의
  밀도를 지키기 위해 3택을 유지한다.
- 재료 카드에 다음 융합, 필요한 짝 경로, 현재 랭크를 표시해 조합을 완성한
  뒤가 아니라 고르기 전부터 빌드를 계획할 수 있다.
- 월광 전승에 공용 3단계 경로 4종을 추가했다. 구매한 뒤 최대 2종만 장착하며,
  장착한 경로만 다음 런의 카드 풀에 들어간다.
- 월광 전승 UI는 같은 카드 타일을 반복하는 상점형 화면에서 `전승 경로 /
  시작 능력 / 카드 해금` 장부로 바꿨다. 레벨업 카드와 시작 기술표도 반복
  라벨·설명·CTA를 걷어내고 결정에 필요한 문장만 남겼다.
- 메뉴 테마는 캐릭터 선택과 로드아웃 확인까지 유지하고, 런 진입 시 인게임
  4곡의 무작위 비중복 순환으로 전환한다. 캐릭터 선택, 강화 확정, 클래스별
  QWER·D·F에는 CC0 실음과 합성음을 겹친 전용 피드백을 연결했다.

## ① XP 젬 드랍 + 자석 수집 루프 (P0)

### 왜

뱀서 도파민의 근원은 "죽이기"가 아니라 **"쓸어담기"**다. 몹몰이 → 광역기 →
바닥에 깔린 젬 융단 → 걸어가며 주르륵 흡수. 이 시각·촉각 보상이 지금은 없다 —
처치 순간 XP가 조용히 숫자로 들어온다.

### 설계

- 적 사망 시 XP 젬을 바닥에 남긴다. 기존 `grantXp` 즉시 지급을 젬 경유로 바꾼다.
- 플레이어 반경 `pickupRadius`(기본 2.5 정도) 안에 들어오면 가속하며 빨려온다.
  `src/sim/rewards.ts`의 인장이 이미 끌림(`RELIC_ATTRACT_SPEED`)·픽업 판정 구조를
  갖고 있다 — 이 패턴을 일반화한다.
- 티어 병합: 같은 자리에 젬이 쌓이면 상위 티어 1개로 합친다(워커 1 → 청색,
  브루트 4 → 녹색, 정예 12 → 금색). 뱀서의 "바닥이 보석으로 변하는" 그림과
  동시에 개체 수 상한을 지킨다.
- **새 강화 축이 공짜로 생긴다**: "픽업 반경 +30%" 카드(④와 연동), 자석
  아이템(②와 연동).

### 구현 방향

- `src/sim/`에 SoA 풀 추가 (enemies.ts의 `EnemyPool` 패턴 그대로: Float32Array +
  swap-remove + `views` 자동 수집). 상한 256이면 충분하다(티어 병합 전제).
- 흡수 시점에만 `grantXp` 호출 → `awaitingChoice` 동기화 규약이 그대로 유지된다.
- 렌더: InstancedMesh 1드로우. `src/render/enemies.ts`의 인스턴싱 패턴 재사용.

### 주의 — 결정론과 XP 곡선

- 젬 이동은 고정 틱 안에서만 적분한다. 난수 불필요(사망 위치에서 생성).
- **XP 지급이 "사망 즉시"에서 "수 초 뒤 흡수"로 밀리므로 레벨업 타이밍이
  뒤로 드리프트한다.** `src/sim/progression.ts`의 `TARGET_LEVEL_TIMES`는 비트
  시트이므로, 젬 도입 후 `npm run balance`로 실측해 `XP_FOR_NEXT`를 재보정해야
  한다. 보정 없이 넣으면 현재 0:12 첫 레벨업 비트가 어긋난다.
- 멀리 떨어진 젬은 바닥의 이동 목표로 남긴다. 20초 후 전역 자동 흡수처럼
  거리 규칙을 무시하는 예외는 두지 않고, 전장 자석을 획득했을 때만 모든 젬을
  끌어온다. 풀 상한을 넘긴 XP는 기존 젬에 병합하므로 수치 자체는 유실되지 않는다.

### 검증

`npx tsx tools/_survive.ts` + `npm run balance` 둘 다. 레벨 도달 시각이
`TARGET_LEVEL_TIMES` 대비 ±3초 안에 들어올 때까지 `XP_FOR_NEXT` 조정.

## ② 바닥 픽업 3종 (P0)

### 왜

지금 카이팅은 "적이 없는 쪽으로"라는 소극적 선택뿐이다. 바닥에 주울 것이
있으면 **"저길 주우러 갈 것인가"라는 위치 결정**이 생기고, 도망 방향에 이유가
붙는다. 뱀서의 닭다리·자석·폭탄이 정확히 이 역할이다.

### 설계

| 픽업 | 효과 | 드랍원 | 확률(초안) |
|---|---|---|---|
| 회복 오브 | 즉시 HP 30 | 브루트 | 12% |
| 자석 | 전장의 모든 젬 즉시 흡수 | 러셔 | 1.5% |
| 섬멸탄 | 화면 안 일반몹 전멸(보스·정예 제외) | 브루트 | 2% |

- 자석·섬멸탄은 **①의 젬이 있어야 가치가 산다**. ① 이후에 넣는다.
- 섬멸탄은 처치 XP를 그대로 지급한다(젬으로 뿌린다) — 벌점이 아니라 잭팟.
- 드랍 추첨은 사망 처리(`src/sim/damage.ts:127` 근처, `dropRelic` 호출부와 같은
  자리)에서 `world.rng`로 굴린다. **반드시 world.rng만 쓴다** — 결정론 규약.

### 구현 방향

- ①과 같은 SoA 풀에 `type` 필드만 추가해 젬과 픽업을 한 풀에서 관리해도 된다
  (상한 공유, 렌더 1드로우 유지).
- 인장과 달리 픽업은 **밟아야** 먹는다(자동 끌림 없음). "주우러 가는 결정"이
  핵심이므로 인장의 자동 지급 관용을 복사하면 안 된다.
- 섬멸탄 연출은 `world.rings` + `src/render/impact.ts`의 화면 흔들림 재사용.

### 주의

- 회복 오브가 `KILL_HEAL_RATE`(초당 4, 상한 12)의 존재 이유를 침식하지 않게
  드랍률을 낮게 시작한다. 계측 기준: 5분 총회복에서 오브 비중 25% 이하.

## ③ 런 간 메타 진행 (P0)

### 왜

뱀서 리텐션의 절반은 "이번 판 골드로 다음 판이 조금 강해진다"다. 지금 이
게임에서 다음 판을 또 하게 만드는 힘은 순수 점수뿐이다 — 가장 큰 공백.

### 설계

두 층으로 나눈다. **언락이 주(主)고 영구 스탯은 종(從)이다** — 영구 스탯을
크게 주면 밸런스 계측(`tools/_survive.ts`)의 전제가 무너지기 때문이다.

1. **월광(재화)**: 런 종료 시 `computeScore().total / 100`을 지급.
   `src/sim/score.ts`가 이미 결정론적 점수를 만들므로 환산만 얹는다.
2. **언락 (핵심)**: 신규 카드·합성(④에서 추가분)은 처음엔 잠금. 조건 달성
   또는 월광 구매로 해금. "다음 판에 새 카드가 풀에 섞인다"가 보상이다.
   - 예: 「처형」 카드 = 누적 3,000킬 / 「부활」 = 보스 처치 1회
3. **영구 스탯 (소폭)**: 시작 HP +5, 시작 이속 +2% 수준의 5~6칸 트리.
   총합이 런 파워의 8%를 넘지 않게 잡는다.

### 구현 방향

- 저장: `src/ui/records.ts`의 패턴 복사 — 단일 키(`myeongwol-meta-v1`),
  `sanitize`로 숫자 강제 검증, try/catch, 버전 필드.
- **시뮬 결정론 유지**: 메타 상태는 `createWorld` 인자(초기 스탯 보정 +
  카드 풀 필터)로만 들어간다. 시뮬이 localStorage를 직접 읽으면 안 된다 —
  `src/sim/`의 DOM 의존 0 규약(HANDOFF 4장)이 헤드리스 밸런싱의 전제다.
  리플레이·기록에는 메타 스냅샷을 함께 저장해야 같은 입력이 같은 결과를 낸다.
- 카드 풀 필터는 `UpgradeCandidate.available`에 이미 있는 구조로 흡수된다.

### 검증

`tools/_survive.ts`에 "메타 0" / "메타 만렙" 두 프로파일을 추가해 승률 차가
10%p 이내인지 본다. 넘으면 영구 스탯을 깎는다.

## ④ 카드 풀 확장 — 클래스당 12~14종 + 합성 2~3종 (P0)

### 왜

각성(III)·합성 시스템은 이미 잘 만들어져 있는데 **재료가 부족하다**. 클래스당
8종이면 5분 런에서 풀 대부분을 보고, 3판째부터 선택이 반복된다. 빌드 다양성 =
리플레이 가치.

### 설계 — 새 카드 축 (초안)

기존 네이밍 축(일현 = 광학 장치, 월아 = 검술 유파)을 유지한다.

**일현 (광학 장치)**
| 카드 | I / II | III 각성 |
|---|---|---|
| 간섭 필라멘트 | 평타 관통 +1 / +1 | 관통을 다 쓴 광선이 마지막 대상에서 소폭 폭발 |
| 이중 초점 | 보조 광선 1발(피해 40%) / 발사각 축소 | 보조 광선이 점등된 적을 자동 추적 |
| 수광 집열판 | 픽업 반경 +30% / +30% (① 연동) | 젬 흡수마다 0.5초 평타 간격 -35% 중첩 |
| 잔광 축전지 | D 쿨다운 -15% / F 쿨다운 -15% | D·F 사용 시 3초간 공격 피해 +25% |

**월아 (검술 유파)**
| 카드 | I / II | III 각성 |
|---|---|---|
| 단두 일섬 | 평타 피해 +12% / +12% | 체력 18% 이하 일반몹 즉시 처형(보스·정예 제외) |
| 흡월 연공 | 처치 회복 예산 상한 +6 / 회복 속도 +2 | 초과 회복이 다음 피격 1회를 막는 보호막으로 전환 |
| 월영 쌍격 | 평타가 뒤쪽 좁은 부채꼴도 벰(피해 50%) / 후방 피해 +25% | 앞뒤 동시 처치 시 참흔 게이지 +8 |
| 사혈 보식 | 픽업 반경 +30% / 회복 오브 효과 +50% (②연동) | 젬 흡수 10개마다 다음 평타가 2회 타격 |

**합성 추가 (초안)** — 기존 `singularity-interferometer` / `eclipse-sword-codex`와
같은 문법(두 각성 III 요구):
- 일현: 「초신성 표본」 = 이중 초점 III + 간섭 필라멘트 III → 폭발이 연쇄한다
- 월아: 「월식 처형진」 = 단두 일섬 III + 월영 쌍격 III → 처형이 주변에 전파된다

**부활 (공용, 언락 전용)**: 사망 시 1회 부활 + 2초 무적 + 섬멸탄 효과.
③의 언락 보상으로만 풀에 들어온다. 가중치 낮게(3), 랭크 1칸짜리
(합성처럼 `ranks.length === 1` 경로 재사용).

### 구현 방향

- `src/content/upgrades.ts`의 `defineUpgrade` 블루프린트에 그대로 얹는다.
  랭크 검증·클래스 필터·우선순위 노출(`getUpgradeRollPriority`)이 전부 기존
  인프라로 처리된다.
- 새 trait는 `src/sim/kits.ts`의 `hasSkillTrait` / `src/sim/stats.ts` 경로로
  소비한다. **피해는 반드시 `dmg()`를 거친다** — atkDamageMul 미반영 결함이
  과거 두 번 재발한 지점이다(HANDOFF 1-3).
- `DAMAGE_TRAIT_META`(`src/content/skills.ts:237`)에 추가 피해 슬롯을 등록해야
  툴팁 정직성 검증이 따라온다.

### 주의

- 카드가 늘면 각성 도달률이 떨어진다. `getUpgradeRollPriority`의 "진행 중인
  장비 우선" 로직이 이미 이를 완화하지만, 풀 확장 후
  `tools/_survive.ts`로 "런당 각성 도달 횟수"를 계측해 1.5회 이상을 유지한다.

## ⑤ 죽어 있는 타격감 배선 살리기 (P0)

새 기능이 아니라 **이미 만든 재미를 켜는 일**이다. 비용 대비 효과가 가장 크다.

1. **무기 궤적 리본**: `src/render/trails.ts:293`의 `WeaponTrail.burst()`를
   호출하는 곳이 코드베이스에 없다. trails.ts:629의 통합 가이드 [5]단계대로
   renderer의 `consumeCharacterActions`에서 스윙 시점에 `burst()`를 배선한다.
   "근접 타격감의 척추"가 비용만 내고 한 번도 안 그려지고 있다.
2. **셰이더 프리컴파일**: `src/main.ts:203`의 `if (activeRun)` 가드 때문에
   캐릭터 선택 중 렌더가 돌지 않아, skillfx 셰이더 7종 + 후처리 컴파일이 판
   시작 첫 프레임에 몰린다(저사양 수백 ms 히치). 선택 화면 동안 오프스크린
   1회 렌더 또는 `renderer.compileAsync`로 미리 치른다. main.ts:119의 주석이
   약속한 동작이기도 하다.
3. **품질 리셋 버그**: `src/render/renderer.ts:257`의 후처리 품질 판단이
   `qualityChanged`에 걸려 있어 리사이즈 한 번에 low→high로 되돌아간다.
   `constrained` 기준으로 고친다. 모바일 프레임 유지는 타격감의 토대다.

## ⑥ 웨이브 이벤트 — 서지 (P1)

### 왜

뱀서의 공포와 흥분은 "갑자기 화면이 이상해지는 순간"이다(새 떼, 원형 포위,
꽃 벽). 현재 스폰 커브는 밀도만 선형 증가라 90~170초 구간이 단조롭고, 정예
비트(75/145/195) 사이가 비어 있다.

### 설계 — 고정 비트 3종 (초안)

| 시각 | 이벤트 | 문법 |
|---|---|---|
| 1:50 | **포위 링** — 워커 40이 플레이어 중심 반경 14 원형으로 동시 스폰, 조여옴 | 광역기로 한쪽을 뚫는다 (탈출구 만들기) |
| 2:50 | **돌격 행렬** — 러셔 24가 한 방향에서 3열 종대로 돌진 | 옆으로 비킨다 (측면 회피) |
| 4:10 | **월광 홍수** — 보스전 중 워커 소용돌이가 외곽에서 나선 진입 | 보스와 잡몹 사이 공간 관리 |

- 이벤트 몹은 XP를 절반만 주되(뱀서의 이벤트 몹 관용) 젬(①)은 그대로 뿌려
  "이벤트 = 수확 축제"로 읽히게 한다.
- 시작 3초 전 `world.rings` 예고 + HUD 경고(기존 combat-readability 레이어).

### 구현 방향

- `src/sim/rewards.ts`의 `stepEliteRewardBeats`가 정확히 같은 문법이다
  (고정 시각 비트 + 인덱스 소모 + 풀 부족 시 재시도). 이 패턴을 복사해
  `stepSurgeBeats`를 만든다.
- 링 스폰은 각도를 균등 분할하므로 난수 소비가 없거나 시작 각 1회뿐 —
  결정론 유지가 쉽다. `spawnEnemy`의 화면 밖 스폰 링 대신 명시 좌표 스폰
  경로가 필요하다(위 선행 조건 ⑵의 림 접기 수정과 같이 손보면 된다).
- `targetAliveCount` 목표치와 이벤트 스폰이 겹쳐 MAX_ENEMIES(600)를 넘지
  않게, 이벤트 중에는 일반 스포너를 일시 감속한다.

### 검증

`tools/_survive.ts`에 이벤트 시각 전후 위험 시간(최저 체력) 계측을 추가.
이벤트가 "사망 스파이크"가 아니라 "긴장 스파이크"인지 — 이벤트 구간 사망률이
전체의 40%를 넘으면 수량을 깎는다.

## ⑦ 보스 2페이즈 (P1)

### 왜

돌진 속도는 고쳐졌지만(24 > 10.7) 패턴이 하나뿐이라 90초 내내 같은 문법이다.
"읽고 피한다"의 어휘가 1개면 두 번째 사이클부터 긴장이 소멸한다. HANDOFF A'
(보스 재설계)의 남은 절반이기도 하다.

### 설계

HP 50% 진입 시 페이즈 2 — 기존 사이클(선회→예고→돌진→회복)에 **장판 한 수**를
끼운다:

- **월식 장판**: 회복 페이즈 대신, 플레이어 현재 위치 + 예측 위치 2곳에
  반경 3.5 경고 원 → 1.1초 뒤 폭발(피해 28, 접촉 피해와 별개). 서 있으면
  맞고, 움직이면 피하는 가장 고전적인 문법.
- 페이즈 2 돌진은 끝점에 소형 장판 1개를 남겨 "피했는데 밟는" 이중 읽기를
  만든다.
- 전환 연출: HP 50% 도달 틱에 1.2초 무적 + 전 잡몹 넉백(`world.rings` +
  화면 흔들림) — 페이즈가 바뀌었음을 몸으로 알린다.

### 구현 방향

- `src/sim/enemies.ts`의 보스 페이즈가 **월드 시간만으로 결정되는** 구조
  (`bossPhaseAt`)이므로, 페이즈 2 여부는 `world.boss`에 hp 임계 플래그 하나로
  추가하고 사이클 표를 분기한다. 난수·타이머 배열 불필요 — 기존 결정론
  문법이 유지된다.
- 장판은 `src/sim/zones.ts`의 기존 지연 폭발(`fireAt`) 경로를 재사용한다.
  적이 소유한 장판이라는 점만 다르다(피해 방향 반전).
- 예고 렌더는 돌진 예고(`bossChargeDir` 텔레그래프)와 같은 계층에 얹는다.

### 주의

- 보스 HP 2,600은 "스킬 밸류 작업 후 다시 올린다"는 보류 상태다
  (enemies.ts:63 주석). 페이즈 2를 넣으면 전투 시간이 늘어나므로 HP 상향과
  같은 커밋에서 계측하지 말 것 — 변수를 하나씩 움직인다.

### 검증

`tools/_survive.ts`의 보스 진행도 계측으로 승률 확인. 목표: 두 클래스 모두
승률 35~65% 구간(현재 계측 인프라가 이미 있다).

## ⑧ 승리 후 이어하기(엔드리스) / 하드 모드 (P1)

### 왜

5분 승리가 곧 콘텐츠의 끝이라, 잘하는 플레이어일수록 빨리 떠난다. 뱀서의
30분 벽·하이퍼 모드, 이터널리턴의 랭크 반복이 하는 일 — "끝난 뒤에도 오를
축"이 없다.

### 설계

1. **이어하기**: 보스 격파 시 결과 화면에 "계속 싸운다" 선택지. 수락하면
   - 스폰 목표치가 `targetAliveCount` 마지막 값에서 30초당 +12씩 증가
   - `enemyHealthMultiplier`가 1.55에서 계속 선형 상승 (상한 해제)
   - 정예가 40초마다 재등장(전리품은 계속 나온다 — ④의 확장 풀 소화처)
   - 사망 시각이 곧 기록. 점수에 "생존 연장" 축 추가
2. **하드 모드 (월식)**: 메인 메뉴 토글. 적 속도 +10%, 접촉 피해 +25%,
   점수 배율 ×1.5. ③의 언락 조건(첫 승리)으로 개방.

### 구현 방향

- `RUN_TIME_LIMIT`(300) 이후를 허용하는 분기: `src/sim/world.ts:242`의
  timeout 판정을 "이어하기 수락 시 스킵"으로 바꾸고, `world.endless` 플래그를
  `createWorld` 인자로 받는다(③과 같은 규약 — 시뮬은 인자로만 받는다).
- 스폰 커브는 `SPAWN_CURVE` 마지막 점 이후 외삽 함수 하나 추가로 끝난다
  (`targetAliveCount`가 이미 마지막 값 유지 구조라 확장 지점이 명확하다).
- 점수: `src/sim/score.ts`에 `endless` 항 추가. 기록 스키마는
  `records.ts`의 sanitize에 필드 검증을 더해 버전 태그를 올린다(v1 레코드
  하위 호환 유지 — 필드 없으면 0).
- 레벨은 MAX_LEVEL(26) 이후 "스킬 랭크 무한 반복" 또는 "XP → 점수 환산"
  중 택1. 전자가 뱀서답다(`LEVEL_REWARDS`의 `?? 'skill-rank'` 폴백이 이미
  그 방향을 가리키고 있다).

### 주의

- MAX_ENEMIES 600과 질의 버퍼(`src/sim/query.ts:20`의 512,
  `src/sim/enemies.ts:486`의 96)가 밀도 상승의 상한이다. 엔드리스에서 스폰
  상한을 올리려면 **버퍼 크기를 먼저 올려라** — 512 < 600은 현재도 잠복
  결함이다(조용한 판정 누락).
- 60fps 유지가 한계 밀도를 정한다. InstancedMesh라 드로우는 문제없지만
  분리 조향 O(n·이웃)이 지배 비용이다. 엔드리스 목표 밀도는 계측으로 정한다.

## 권장 착수 순서와 의존 관계

```
선행   버그 수정 (W중 점멸, 림 스폰, 슬롯 드래그, pause await, 품질 리셋)
⑤     배선 살리기            ← 코드 하루, 체감 즉시
①     XP 젬 루프             ← ②·④(픽업 카드)·⑥(수확 축제)의 토대
③     메타 진행(언락 중심)    ← ④(신규 카드)의 소화처
④     카드 확장              ← ⑦·⑧의 밸런스 여유를 만든다
⑥     서지 이벤트
⑦     보스 2페이즈           ← 이후 보스 HP 재상향(보류 중)과 별도 계측
⑧     엔드리스 / 하드 모드    ← ③의 언락과 연결
```

밸런스 수치를 만지는 모든 단계에서 `npx tsx tools/_survive.ts`(생존)와
`npm run balance`(XP 곡선)를 **둘 다** 돌린다. 후자만 보면 무적 봇의 숫자만
본다(HANDOFF 0장).
