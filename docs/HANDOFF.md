# HANDOFF — 상용 품질 완료 상태와 회귀 계약

이 문서는 과거 결함 목록이 아니라 **현재 구현과 검증 기준**을 기록한다.
검증 기준 커밋은 이 파일이 포함된 `main`이며, 정확한 값은
`git rev-parse --short HEAD`로 확인한다.

## 1. 현재 플레이어 경험

| 영역 | 완료 상태 |

| 패시브 UI | 전투 HUD에서 패시브를 QWER와 같은 슬롯 형태로 표시한다. 루멘은 「점등」, 월아는 「참흔 · 월참」의 현재 상태와 수치를 실시간으로 보여준다. |

## 2. 현재 밸런스 기준선

고정 12시드 × 2클래스의 최신 로컬 회귀 결과다.

| 항목 | 루멘(원거리) | 월아(근거리) | 계약 |
|---|---:|---:|---|
| 기본 HP | 125 | 130 | 근접이 더 높고 피해 감소·회복까지 포함해 전열 역할을 가진다 |
| Lv26 중앙값 | 4:45.1 | 4:49.8 | 목표 4:52 ±8초, 클래스 차이 10초 이하 |
| QWER 처치율 상승 | 3.96× | 2.34× | 자동 평타 기준보다 시드별 1.5× 이상 |
| 필멸 파일럿 승리 | 9/12 | 11/12 | 각 클래스 50~92%, 원거리 최소 8승 |
| 보스 진행도 중앙값 | 100% | 100% | 각 클래스 80% 이상 |
| 최저 체력 중앙값 | 52% | 48% | 위험 구간이 실제로 발생해야 한다 |
| 순 HP 손실 중앙값 | 616 | 510 | 회복까지 반영한 틱간 순감소 합계 |
| 피격 틱 중앙값 | 19.8% | 15.7% | 접촉·돌진·장판을 모두 포함한 HP 순감소 틱 비율 |

추가 고정값:

- 동시 적 목표 상한: 135
- 보스 HP: 2,600
- 정예 보상: 한 판 3회
- 최대 레벨: 26
- 플레이 시간: 5분

`순 HP 손실`은 원시 피해량이 아니다. 같은 틱의 회복은 손실을 상쇄한다.
`피격 틱`도 몸 접촉률이 아니라 모든 피해 원인을 포함한다. 생존 판단에는
승리 수, 최저 체력, 위험 시간, 보스 진행도를 함께 사용한다.

## 3. 자동 검증 계약

| 명령 | 보장하는 것 |
|---|---|
| `npm run check` | 시뮬 규칙, 전체 상태 결정론, 전투, XP 보석, 픽업, 급습, 강화, 렌더 품질 정책, 기록, VRMA를 모두 검사한다 |
| `npm run build` | TypeScript, Vite 프로덕션 번들, Sites 배포 산출물을 검증한다 |
| `npm run balance` | 12시드 × 2클래스의 Lv26 곡선과 QWER 처치율을 비교한다 |
| `npm run balance:survival` | 실제 선택·이동·회피·D/F를 쓰는 필멸 파일럿의 승리와 위험도를 검사한다 |
| `git diff --check` | 공백 오류와 충돌 흔적을 검사한다 |

### 결정론

`tools/determinism-check.ts`는 같은 시드와 같은 입력을 세 월드에 넣고
1·3·8틱 묶음을 **교차 실행**한다.

- 플레이어, 보스, 진행도, 스킬, 강화, 보상, 세 RNG를 비교한다.
- 적·XP 보석·전장 픽업의 활성 typed-array 구간은 원시 바이트로 비교한다.
- 위험 장판, 예약 타격, 궁극기, 누적 이벤트 스트림도 비교한다.
- 실제 런타임 카드 생성·적용 경로로 해금, 스킬 랭크, 강화, 정예 인장을 소비한다.
- 렌더 보간용 `prev*`, 체력바 표시 시간처럼 다음 시뮬 틱에 영향을 주지 않는
  장식 상태만 의도적으로 제외한다.

이 검사는 같은 JS 프로세스 안의 권위 상태 재현을 보장한다. 서로 다른 CPU·JS
엔진 사이의 바이너리 호환성까지 주장하지 않는다.

### VRMA 재현

`tools/generate-vrma.ts`의 `generateVrmaBytes()`는 파일을 쓰지 않는 순수 생성
경로다. `npm run check`는 다음 세 바이트 배열이 모두 같은지 검사한다.

1. 메모리 생성 1회차
2. 메모리 생성 2회차
3. 커밋된 `public/animations/myeongwol-combat.vrma`

그 뒤 18개 전체의 GLB 구조·본 트랙·쿼터니언·정규화, 전투 14개 클립의 단계,
수평(X/Z) 루트 이동 부재, QWER·궁극기 판정 시점, QWER 실루엣을 검사한다.

## 5. 성능·에셋 동작

- 메인 메뉴에서 약 20MB인 VRM 두 개를 일괄 선로딩하지 않는다. 접근성용 첫 카드 자동 포커스는
  요청을 만들지 않으며, 사용자가 `focus` 또는 `pointerenter` 상태에 머문 카드만 새로 요청한다.
  전환 전에 이미 시작한 전송은 겹칠 수 있다.
- 다른 카드로 이동한 뒤 도착한 파싱 결과는 보관하지 않고
  `VRMUtils.deepDispose()`로 정리한다.
- 이미 시작된 GLTF HTTP 전송 자체는 취소할 수 없다. 사용 중인 리그는 참조 수로
  보호하고, 클래스 교체 뒤 분리된 모델만 폐기한다.
- 실제 모바일은 절차식 캐릭터와 blob shadow를 사용한다. 같은 애니메이션
  그룹 안의 정적 형상을 병합해 루멘 84, 월아 74 draws까지 낮췄다.
- 작은 화면·coarse pointer는 DPR 최대 1.35, 실시간 그림자 끔, 저품질 후처리를 쓴다.
- 그 외 기기도 3초 워밍업 뒤 EMA 기준 약 42 FPS 미만이 4초간 지속될 때 한 번 제한 tier로
  내려간다. 250ms 이상 탭 정지와 50 FPS 이상 회복은 누적을 초기화한다.
  플레이 중 품질을 다시 올려 진동시키지는 않는다.

## 6. 수정할 때 지켜야 할 것

1. `src/sim/`에는 DOM·three.js·벽시계·`Math.random()`을 넣지 않는다.
2. 모든 권위 난수는 `world.rng`, `choiceRng`, `pickupRng` 중 목적에 맞는
   스트림을 사용한다.
3. 피해 경로는 `world.stats`와 스킬 랭크 배율을 우회하지 않는다.
4. 스킬 설명·실제 판정·애니메이션 타격 시점은 같은 변경에서 함께 고친다.
5. 밸런스 수치를 바꾸면 `balance`와 `balance:survival`을 둘 다 돌린다.
6. 렌더 변경은 데스크톱 VRM과 `?model=procedural` 모바일을 모두 확인한다.
7. 낯선 작업 파일을 삭제하거나 `git add -A`로 섞지 않는다. 병렬 작업자의
   미커밋 변경과 사용자 소유 untracked 파일을 보존한다.

## 7. 의도적으로 남긴 제약

- 생존 수치는 12개 고정 시드의 로컬 회귀다. 라이브 텔레메트리나 전체 유저
  승률을 대체하지 않는다.
- VRM 원본의 배포 권한이 제한적이므로 Sites 프로덕션은 공개 전환하지 않고
  비공개 접근으로 유지한다.
- 이미 시작된 VRM 다운로드는 취소하지 못하지만, 사용하지 않는 파싱 결과와
  GPU 자원은 보관하지 않는다.

현재 기능성 P0/P1 미완료 항목은 없다. 새 변경이 위 계약을 깨면 완료 이력이
아니라 회귀로 취급한다.
