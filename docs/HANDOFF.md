## 0. 먼저 알아야 할 것 — 계측 도구의 함정

`tools/balance/`의 시나리오는 **승률과 위험도를 잴 수 없다.**

```ts
// tools/balance/model.ts
if (options.invulnerable ?? true) {          // 기본값이 true
  world.player.invulnUntil = Number.POSITIVE_INFINITY
}
// input.move 는 이 파일 전체에서 한 번도 대입되지 않는다 → 봇이 제자리에 선다
```

리포 어디서도 `invulnerable: false`를 넘기지 않는다. 즉 **무적으로 제자리에
선 봇**이 5분을 버틴 결과가 "밸런스 측정치"로 쓰이고 있었다. XP 곡선 보정에는
타당하지만(입력 변수를 제거하므로), 이걸로 "적이 약하다"를 잡아낼 수는 없다.

생존 측정은 `tools/_survive.ts`로 한다(gitignore, `npx tsx tools/_survive.ts`).
필멸이고, 카이팅하고, 클래스별로 회피 반경이 다르며(근접은 사거리 안으로
파고든다), D/F를 상황에 맞춰 쓴다. 측정 항목은 승률·최저체력·위험시간·
접촉률·보스 진행도다.

**밸런스를 건드리면 이걸 돌려라.** `npm run balance`만 보면 안 죽는 봇의
숫자만 본다.

## 1. 적대적 검토에서 확인된 결함

20 에이전트가 5개 관점으로 검토하고 각 지적을 반증 전제로 재검증했다.
아래는 **반증에 살아남은 것**만 추렸다. 심각한 순.

### 1-1. 시전 중 이동하면 스킬이 빗나간다 (blocking)

`20ffab3`이 평타·QWER 전부에 선딜 + 이동/조준 잠금을 넣었고,
`dd43ab8`("Restore responsive basic attacks")이 평타만 즉발로 되돌리면서
**QWER의 선딜은 남긴 채 이동/조준 잠금만 통째로 제거**했다.

결과: 스킬은 **시전 시점의 각도**를 고정한 채 **판정 시점의 위치**에서
발사된다. 5분 서바이버에서 플레이어는 항상 움직이므로 이건 예외가 아니라
기본 경로다.

측정된 손실:
- 일현 R: 군중 75마리 중 15마리만 명중 (127,500 → 25,500 피해)
- 단일 대상 Q: 70 → 0

고칠 방향은 둘 중 하나다. (a) 판정 시점에 각도를 다시 계산한다,
(b) 시전 중 이동 잠금을 되살린다. (b)는 조작감을 해치므로 (a)를 권한다.

### 1-2. 시전 중 QWER 입력이 조용히 버려진다 (major)

`playerAction` 게이트가 시전 중 들어온 스킬 입력을 버퍼 없이 버린다.
런당 139~1,475회, 러닝 타임의 **17~22%가 입력 불감 구간**이다.
스킬바는 그동안에도 "사용 가능"으로 남아 있어 유저는 왜 안 나가는지 모른다.

최소 수정: 짧은 입력 버퍼(0.15초)를 두거나, 불감 구간 동안 스킬바를
회색 처리해 상태를 정직하게 보여준다.

### 1-3. `atkDamageMul`이 QWER 8종에 0% 반영된다 (major)

「예리함」·「광폭화」 같은 공격력 카드가 **평타에만** 먹고 스킬에는 전혀
안 먹는다. 점등 평타에도 광고의 절반 이하만 들어간다.
스킬 랭크업(rank0→4 = 1.8배)은 8종 전부 정상 동작한다.

과거에 같은 부류의 결함을 한 번 고쳤는데(커밋 `c17`) 새 경로에서 재발했다.
`world.stats`를 우회하는 피해 경로가 생기면 카드가 광고와 다르게 동작한다.

### 1-4. 보스가 플레이어를 한 번도 못 때린다 (major)

보스 돌진 속도 5.27 < 플레이어 속도 10. 90초 보스전 내내 **접촉 피해가 정확히 0**이다.
이번 diff가 추가한 windup(0.8초 완전 정지)이 오히려 더 못 잡게 만들었다.

보스전이 위협이 되려면 돌진 속도가 플레이어보다 빠르거나(예고를 보고 피하는
문법), 장판·투사체로 공간을 뺏어야 한다.

### 1-5. 월아 E「월륜」이 설명과 다르게 동작한다 (major)

`fireAt: now + 0.3` → `fireAt: now`로 바뀌면서 "끌어모아 통째로 벤다"는
약속이 깨졌고, 유효 타격 반경이 9.4 → 6.4(**면적 −54%**)로 줄었다.

`src/content/skills.ts`의 설명문과 `src/sim/kits.ts` 구현을 **전부 대조**해야
한다. 사용자가 직접 지적한 12번("원거리 E에 밀치기가 없는데 툴팁엔 있다고
나옴")도 같은 부류다.

### 1-6. 평타 스윙 애니메이션의 50%가 재생되지 않는다 (major)

`dd43ab8`이 `vrm-animation`의 `RECOVERY_START`를 지우면서, 「속사」 카드 한 장만
먹어도 평타 스윙의 정확히 **절반이 재생되지 않는다**(30초 실측 60/120).
게다가 `tools/animation-check.ts`가 그 회귀를 테스트로 고정해버렸다 —
테스트가 버그를 승인하고 있다.

### 1-7. 기록 뷰어 결함 3건 (minor)

- 손상된 기록 한 줄이 「점수 기록」 버튼을 **아무 표시 없이 완전히 죽인다**
- 데스크톱 1280px에서 기록 표의 마지막 열이 44px 잘린다(모바일 375px는 정상)
- `prefers-reduced-motion` 목록에 새 오버레이만 빠졌다

접근성(role=dialog, 포커스 트랩, Esc, 포커스 복귀)은 전부 정상 동작을 확인했다.

### 1-8. 테스트 스위트의 검출력이 한 곳에 몰려 있다 (major)

71개 뮤턴트로 뮤테이션 테스트를 돌린 결과 **스코어 73%**(KILLED 52 / SURVIVED 19).
그런데 119개 check 중 한 번이라도 발화한 것은 **21개뿐**이고, KILLED 52건 중
36건(69%)은 `tools/balance/baseline.ts`의 스냅샷 숫자 6줄에만 의존한다.

살아남은 19개 뮤턴트의 구성이 문제다 — 접촉 피해 3종, 동시 피격 캡,
`damageTakenMul`, 플레이어 체력·이동속도·가속, 소환사 주문 D/F 전부,
원거리 흡혈. 즉 **"플레이어가 죽느냐"는 축 전체가 무방비다.**
원인은 0번 항목(무적 봇)이다.

### 반증되어 고칠 필요 없는 것

- **결정론은 무사하다.** 같은 시드·같은 입력이면 최종 상태가 비트 단위로
  일치하고(1틱/3틱/8틱 분할 교차 실행 포함), sim 전체에 `Math.random`·
  `Date.now`·`performance.now`·DOM·three.js가 0건이며 Set/Map은 `has`/`add`로만
  쓰여 순회 순서 의존이 없다.
- `.vrma`는 생성기에서 **바이트 단위로 재현**된다(md5 일치 확인). GLB 청크
  경계·쿼터니언 정규화·루트 모션 부재·공식 로더 왕복까지 실검증한다.
  이 리포에서 가장 견실한 부분이다. 다만 생성 원본(`VRM_TIMING`/`VRM_POSES`/
  `VRM_REST`)에는 커버리지가 0이다.

아래는 이번 작업에서 실제로 적용한 의존 순서다. 현재 A~F와 A'은 모두 완료됐다.

E  UI · 툴팁          2 3 11 12            ← 완료

### A' 보스 (작업 전 계측)

작업 전 보스 체력은 2,600이었다. 당시 계측상 근접 65% / 원거리 15%로
**승리 0/24**였다.
원거리의 단일 대상 DPS가 근본적으로 부족한 것이 원인이고, 이건 C블록
(16번 "Q 밸류가 낮음")으로 풀어야지 체력 조절로는 안 된다.
C를 끝낸 뒤 보스 체력을 다시 올려 잡아라.

### B 강화 카드 — 설계 방향

현재 13장이 전부 "+N%"다. 뱀서라이크의 재미는 **같은 카드를 모으면 질이
바뀌는** 데서 나온다. 제안:

- 각 카드에 **랭크 I·II·III**를 둔다. 같은 카드를 다시 뽑으면 랭크가 오른다
- **랭크 III에서 각성** — 수치가 아니라 성질이 바뀐다
  (예: 「집광 렌즈」 III = 관통할 때마다 피해가 누적된다)
- 특정 **두 각성의 조합**에서만 등장하는 합성 카드
- 네이밍을 장비·각인 계열로 통일한다(사용자 요청 7번).
  일현은 렌즈·프리즘·코어 같은 **광학 장치**, 월아는 연마·보법·호흡 같은
  **검술 유파**로 축을 나누면 두 클래스의 정체성이 카드에서도 드러난다
- **8번**: `UpgradeDef`에 클래스 필터를 넣어라. 근접에 사거리 카드가 나오면
  안 된다. `rollUpgrades`가 `world.playerClass`로 거른다

### C 스킬 — 사용자 지적 요약

- **13**: 근접 R이 광역 느낌이 안 난다. 뱀서는 몹몰이해서 쓸어담는 게임이다
- **14**: 원거리 W를 밀어내는 장판 → **한곳으로 모으는** 장판으로.
  회피성도 강화
- **15**: 원거리 Q와 R의 쓰임새가 같다. Q를 직선 발사가 아닌 것으로 교체
- **16**: 양쪽 Q 모두 밸류가 너무 낮다

C를 할 때 1-1(시전 중 이동 시 빗나감), 1-3(`atkDamageMul` 미반영),
1-5(설명과 구현 불일치)를 **같이** 고쳐야 한다. 셋 다 같은 파일을 만진다.

## 4. 작업 규약

- `src/sim/`은 three.js·DOM 의존 0이고 결정론적이다. 이건 헤드리스 밸런싱의
  전제 조건이라 취향이 아니다
- 밸런스 수치를 바꾸면 `npx tsx tools/_survive.ts`와 `npm run balance`를
  **둘 다** 돌려라. 앞은 생존, 뒤는 XP 곡선이다
- `npm run check`의 밸런스 스냅샷 단언 3건은 현재 **보류 상태**다.
  설계가 안정되면 다시 떠야 한다(`tools/sim-check.ts`에 이유를 주석으로 남겼다)
- 주석은 한국어로 **왜**를 쓴다. 코드가 이미 말하는 "무엇"을 반복하지 않는다

## 5. 병렬 작업 사고 기록

이 리포는 한동안 두 주체가 동시에 편집했고, 그 과정에서 한쪽이 다른 쪽의
