# HANDOFF — 상용 품질 완료 상태와 회귀 계약

이 문서는 과거 결함 목록이 아니라 **현재 구현과 검증 기준**을 기록한다.
검증 기준 커밋은 이 파일이 포함된 `main`이며, 정확한 값은
`git rev-parse --short HEAD`로 확인한다.

## 1. 현재 플레이어 경험

| 영역 | 완료 상태 |
|---|---|
| 캐릭터 선택 | 루멘·월아 초상의 높이와 정보 밀도를 통일했다. 카드에는 플레이 스타일·핵심 강점·패시브만 먼저 보여주고, 선택 뒤 전투 브리핑에서 `Q W E R · P · D F`의 이름·역할·효과와 해금 시점을 확인한 다음 시작한다. |
| 패시브 UI | 전투 HUD에서 패시브를 QWER와 같은 슬롯 형태로 표시하되 「자동」 상태임을 분리한다. 루멘은 점등 대상 수, 월아는 참흔 게이지를 각 의미에 맞게 실시간으로 보여준다. |
| QWER | 두 클래스 8개 스킬의 역할·판정·툴팁을 일치시켰다. 루멘 Q 「삼중 굴절」은 5초간 평타를 중심 100%+보조 30%×2로 강화하고, W 「광도약」은 커서 방향 8거리로 전진한다. QWER는 누른 순서대로 0.25초 예약되며 쿨 종료 0.18초 전 입력도 받아 준다. |
| 조작 | 마우스 이동은 도착점 2.6거리부터 자연스럽게 감속하고 0.55거리에서 멈춘다. HUD 위 포인터는 전장 조준을 흔들지 않으며, 약한 조준 보정은 커서에 가까운 적만 보정하고 설정에서 끌 수 있다. 일반 시전 드래그, 입력 해제·포커스 이탈, 궁극기 중 예약·점멸도 회귀로 잠갔다. |
| 애니메이션 | idle/walk 4개와 평타·강화 평타·QWER 전투 14개, 총 18개 VRMA 클립을 연결했다. 전투 클립은 준비→타격→회복 단계를 가지며 빠른 공격에서도 스윙이 누락되지 않는다. |
| 자동 평타 | 원거리는 조준 원뿔에 묶이지 않고 실제 가까운 적을 기본으로 잡는다. 군집 표적은 최근접 거리의 1.3배 안에서만 우선해 직관성과 생존력을 함께 보존한다. |
| 강화 | 클래스별 기본 경로 12종에 장착형 공용 전승 경로 4종과 합성 경로를 제공한다. 일반 레벨업은 4택, 정예 전리품은 3택이며, 재료 카드에서 이어지는 융합과 짝 경로 진행도를 미리 보여준다. |
| 5분 아크 | Lv2 약 12초, Lv3 약 25초에 첫 스킬과 첫 강화를 연다. Lv5 누적 XP와 전체 XP 총량은 유지한 채 초반 선택만 앞당겼다. XP 보석은 4 거리 안의 모든 보석이 동시에 귀환하며, 이후 픽업·세 차례 급습·정예·보스 1·2페이즈로 이어진다. |
| 보스 | 예고선→고정 방향 돌진→회복과 2페이즈 예측 장판을 사용한다. 직선 도주만으로 무력화되지 않고, 회피 가능한 경고 시간을 유지한다. |
| 월광 전승 | 전승 경로 4종을 구매하고 최대 2종만 장착한다. 장착 경로는 다음 런의 3단계 카드 풀에만 들어가 6가지 조합을 만들며, 영구 체력·이동 강화와 조건/월광 카드 해금도 런 시작 스냅샷으로만 적용한다. |
| 월식·무한전 | 첫 보스 격파 뒤 월식 난이도가 열린다. 승리 후 같은 월드를 이어 무한전에 진입할 수 있으며, 30초 밀도 상승·지속 체력 상승·40초 정예·만렙 이후 QWER 반복 연마가 이어진다. |
| 메뉴·HUD | 월광 전승은 반복 카드 상점 대신 `전승 경로 → 시작 능력 → 카드 해금` 장부로 재구성했다. 레벨업 카드는 경로·즉시 효과·III 결과만 남기고, 시작 기술표는 `QWER · P · DF` 순서와 사용 시점을 한 번씩만 표시한다. |
| 오디오 | 메뉴에서는 `mainmenu.mp3`를 이어 재생하고 실제 런이 시작되면 즉시 중단한다. 인게임 4곡은 셔플 백으로 중복 없이 순환한다. 루멘·월아 선택음과 클래스별 QWER·D·F, 강화 선택음은 CC0 샘플과 합성음을 겹쳐 구분하며 설정에서 BGM과 효과음을 따로 조절한다. |
| 전투 가독성 | 클래스색 표적 링, 보스 경고, 피해 숫자, 타격 정지, 화면 흔들림, 비네트, 블룸, 스킬 범위 미리보기를 겹침 우선순위에 맞춰 조정했다. |
| 접근성·기록 | 키보드 선택, 포커스 트랩, Esc, 포커스 복귀, reduced-motion, 손상 기록 격리, 1280px 표 잘림 방지를 적용했다. |

## 2. 현재 밸런스 기준선

곡선은 고정 12시드, 생존은 고정 24시드 × 2클래스의 최신 로컬 회귀 결과다.

| 항목 | 루멘(원거리) | 월아(근거리) | 계약 |
|---|---:|---:|---|
| 기본 HP | 125 | 130 | 근접이 더 높고 피해 감소·회복까지 포함해 전열 역할을 가진다 |
| Lv2 / Lv3 중앙값 | 0:11.3 / 0:23.4 | 0:13.2 / 0:25.1 | 목표 0:12 / 0:25 ±3초 |
| Lv26 중앙값 | 4:56.7 | 4:56.8 | 목표 4:52 ±8초, 클래스 차이 10초 이하 |
| QWER 처치율 상승 | 2.80× | 2.26× | 자동 평타 기준보다 시드별 1.5× 이상 |
| 필멸 파일럿 승리 | 23/24 | 20/24 | 각 클래스 50~96%, 원거리 최소 16승 |
| 보스 진행도 중앙값 | 100% | 100% | 각 클래스 80% 이상 |
| 최저 체력 중앙값 | 72% | 66% | D 자동 파일럿은 72% 이하에서 회복하며 실제 위협 구간을 통과한다 |
| 순 HP 손실 중앙값 | 609 | 489 | 회복까지 반영한 틱간 순감소 합계 |
| 피격 틱 중앙값 | 17.6% | 15.6% | 접촉·돌진·장판을 모두 포함한 HP 순감소 틱 비율 |

추가 고정값:

- 동시 적 목표 상한: 135
- 보스 HP: 2,600
- 정예 보상: 한 판 3회
- 최대 레벨: 26
- 초반 XP 요구량: 16 / 36 / 60 / 88 (Lv5 누적 200, 전체 5,643 유지)
- 일반 강화 선택지: 4장, 정예 전리품: 3장
- 장착 전승: 4종 중 최대 2종
- 플레이 시간: 5분
- 월식 난이도: 적 속도 1.1×, 접촉 피해 1.25×, 최종 점수 1.5×
- 무한전: 30초마다 목표 적 +12, 40초마다 정예 1회, 일반 적 체력 배율 지속 상승
- BGM: 메뉴 1곡 루프, 인게임 4곡 셔플 순환

`순 HP 손실`은 원시 피해량이 아니다. 같은 틱의 회복은 손실을 상쇄한다.
`피격 틱`도 몸 접촉률이 아니라 모든 피해 원인을 포함한다. 생존 판단에는
승리 수, 최저 체력, 위험 시간, 보스 진행도를 함께 사용한다.

## 3. 자동 검증 계약

| 명령 | 보장하는 것 |
|---|---|
| `npm run check` | 시뮬 규칙, 전체 상태 결정론, 전투, XP 보석, 픽업, 급습, 전승, 확장 강화, 월식·무한전, 렌더 품질 정책, 기록, VRMA를 모두 검사한다 |
| `npm run check:controls` | QWER 입력 순서·예약, 약한 조준 보정, 도착 감속, 점멸 예외, 루멘 Q 3갈래 평타와 W 커서 방향 도약을 검사한다 |
| `npm run build` | TypeScript, Vite 프로덕션 번들, Sites 배포 산출물을 검증한다 |
| `npm run balance` | 12시드 × 2클래스의 Lv26 곡선과 QWER 처치율을 비교한다 |
| `npm run balance:survival` | 실제 선택·이동·회피·D/F를 쓰는 필멸 파일럿의 승리와 위험도를 검사한다 |
| `git diff --check` | 공백 오류와 충돌 흔적을 검사한다 |

### 결정론

`tools/determinism-check.ts`는 같은 시드와 같은 입력을 세 월드에 넣고
1·3·8틱 묶음을 **교차 실행**한다.

- 플레이어, 보스, 진행도, 스킬, 강화, 보상, 세 RNG를 비교한다.
- 적·XP 보석·전장 픽업의 활성 typed-array 구간은 원시 바이트로 비교한다.
- 위험 장판, 예약 타격, 궁극기, 누적 이벤트 스트림도 비교한다.
- 실제 런타임 카드 생성·적용 경로로 해금, 스킬 랭크, 강화, 정예 인장을 소비한다.
- 렌더 보간용 `prev*`, 체력바 표시 시간처럼 다음 시뮬 틱에 영향을 주지 않는
  장식 상태만 의도적으로 제외한다.

이 검사는 같은 JS 프로세스 안의 권위 상태 재현을 보장한다. 서로 다른 CPU·JS
엔진 사이의 바이너리 호환성까지 주장하지 않는다.

### VRMA 재현

`tools/generate-vrma.ts`의 `generateVrmaBytes()`는 파일을 쓰지 않는 순수 생성
경로다. `npm run check`는 다음 세 바이트 배열이 모두 같은지 검사한다.

1. 메모리 생성 1회차
2. 메모리 생성 2회차
3. 커밋된 `public/animations/myeongwol-combat.vrma`

그 뒤 18개 전체의 GLB 구조·본 트랙·쿼터니언·정규화, 전투 14개 클립의 단계,
수평(X/Z) 루트 이동 부재, QWER·궁극기 판정 시점, QWER 실루엣을 검사한다.

## 5. 성능·에셋 동작

- 메인 메뉴에서 약 20MB인 VRM 두 개를 일괄 선로딩하지 않는다. 접근성용 첫 카드 자동 포커스는
  요청을 만들지 않으며, 사용자가 `focus` 또는 `pointerenter` 상태에 머문 카드만 새로 요청한다.
  전환 전에 이미 시작한 전송은 겹칠 수 있다.
- 다른 카드로 이동한 뒤 도착한 파싱 결과는 보관하지 않고
  `VRMUtils.deepDispose()`로 정리한다.
- 이미 시작된 GLTF HTTP 전송 자체는 취소할 수 없다. 사용 중인 리그는 참조 수로
  보호하고, 클래스 교체 뒤 분리된 모델만 폐기한다.
- 실제 모바일은 절차식 캐릭터와 blob shadow를 사용한다. 같은 애니메이션
  그룹 안의 정적 형상을 병합해 루멘 84, 월아 74 draws까지 낮췄다.
- 작은 화면·coarse pointer는 DPR 최대 1.35, 실시간 그림자 끔, 저품질 후처리를 쓴다.
- 그 외 기기도 3초 워밍업 뒤 EMA 기준 약 42 FPS 미만이 4초간 지속될 때 한 번 제한 tier로
  내려간다. 250ms 이상 탭 정지와 50 FPS 이상 회복은 누적을 초기화한다.
  플레이 중 품질을 다시 올려 진동시키지는 않는다.

## 6. 수정할 때 지켜야 할 것

1. `src/sim/`에는 DOM·three.js·벽시계·`Math.random()`을 넣지 않는다.
2. 모든 권위 난수는 `world.rng`, `choiceRng`, `pickupRng` 중 목적에 맞는
   스트림을 사용한다.
3. 피해 경로는 `world.stats`와 스킬 랭크 배율을 우회하지 않는다.
4. 스킬 설명·실제 판정·애니메이션 타격 시점은 같은 변경에서 함께 고친다.
5. 밸런스 수치를 바꾸면 `balance`와 `balance:survival`을 둘 다 돌린다.
6. 렌더 변경은 데스크톱 VRM과 `?model=procedural` 모바일을 모두 확인한다.
7. 낯선 작업 파일을 삭제하거나 `git add -A`로 섞지 않는다. 병렬 작업자의
   미커밋 변경과 사용자 소유 untracked 파일을 보존한다.

## 7. 의도적으로 남긴 제약

- 생존 수치는 12개 고정 시드의 로컬 회귀다. 라이브 텔레메트리나 전체 유저
  승률을 대체하지 않는다.
- VRM 원본의 배포 권한이 제한적이므로 Sites 프로덕션은 공개 전환하지 않고
  비공개 접근으로 유지한다.
- 이미 시작된 VRM 다운로드는 취소하지 못하지만, 사용하지 않는 파싱 결과와
  GPU 자원은 보관하지 않는다.

현재 기능성 P0/P1 미완료 항목은 없다. 새 변경이 위 계약을 깨면 완료 이력이
아니라 회귀로 취급한다.
